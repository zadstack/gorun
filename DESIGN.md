# GoRun design direction

Product context: PRODUCT.md.

## Administrative workspace
All administration pages share a cool neutral work surface (#f7f8fa), white panels, charcoal ink (#20252b), secondary text (#626a73), quiet dividers (#e3e6e8), and restrained petrol (#246b73) action/selection states. Green (#167252) means success; amber and red mean warning and error. Navigation uses the same petrol selection color across categories. The shared admin.css variables own this palette, including authentication and the admin membership surface; public membership retains its published site identity. Flat white sidebar and topbar keep the working area calm. Compact desktop density with 44px mobile controls. Familiar sidebar, search topbar, content area; detail disclosure reduces metadata noise. Self-hosted Zad typography, Arabic RTL with normal letter spacing, logical CSS dimensions and explicit keyboard focus.

### Dashboard workspace

The dashboard uses a neutral cool-gray background (`--bg: #f7f8fa`), dark ink (`--ink: #20252b`), secondary text (`--muted: #626a73`) and quiet dividers (`--line: #e3e6e8`). Content and data panels use white surfaces with subtle 10px corners. Supporting sections use flat rows and native disclosure instead of additional framed cards. Empty pinned tools and canvas sections start collapsed; populated pins and canvases with boards or activity start open. Pin disclosure state and summary focus survive background refreshes. One petrol quick action leads; localized status labels retain restrained green, amber or petrol fills. The compact desktop default places daily actions across the top, content and statistics in the main area, settings and pinned tools in the utility rail (left in Arabic), and operational summaries below the main area. Grid gaps are 12px and panel padding is 16px. Four common settings are visible; the remaining settings use a labeled native disclosure. Setup starts open on desktop and closes initially on phones through progressive enhancement. Personal widget ordering remains available as a saved flowing layout; reset restores the distributed default. The existing Zad font remains. The compact widget composition applies to the dashboard; its neutral palette is shared by every administration page. Content previews, saved public identities and meaningful data/node categories retain their own colors.

### Direct access in the admin shell

The shared admin shell uses the space beside search for public-site viewing, media and analytics; the primary sidebar exposes common content, site-design, menus, team and connections links. A 76px utility rail hosts the existing agents launcher plus labeled theme, template, health, backup and settings links. Its tool lists use the current permission- and preference-filtered `nav` registry; absent modules and hidden destinations stay absent. Hidden dialog links do not reserve rail space. On phones, the same rail links move into the topbar’s labeled More tools disclosure; returning to desktop restores them to the rail. Without JavaScript, the links remain accessible in the page flow. The agents launcher keeps its existing mobile behavior. A grouped directory below dashboard content exposes structure, settings, integrations and operations destinations directly. These are navigation links, not automatic operational actions. A central WorkspaceTools projection allocates each destination once after primary navigation, context tabs and personal pins claim their destinations. Setup and summary widgets omit redundant navigation links while keeping their status information. Pin changes refresh only navigation regions, preserve keyboard focus and leave editor forms intact. Contextual record links and breadcrumbs remain available. Verification and implementation scope are recorded in docs/admin-ui/RESULTS.md.

## Public themes
Ship-with themes are **identity systems** (type, color, spacing, chrome), not opinionated site-pattern layouts. Stable slugs: `default` Classic, `business` Modern, `portfolio` Minimal, `magazine` Serif, `docs` Docs. Looks: editorial (Classic/Serif), clean-technical (Modern), warm-local (Minimal). Classic pairs cream paper (#fffef2) with charcoal actions (#333333). Serif uses neutral white paper and charcoal text, with deep blue (#001489) for actions and links so images carry the color. References: [Kobbe](https://ui.gradientdeck.com/styles/kobbe), [Aesop](https://ui.gradientdeck.com/styles/aesop), [MUBI Notebook](https://ui.gradientdeck.com/styles/mubi-notebook). Site brand and content own the voice; saved identities override defaults. Keep CSS scoped by data-theme. Full site patterns (magazine/business/portfolio packs) belong in plugins, not the theme catalog.

## Constraints
Selected homepage heroes may use a self-hosted Three.js enhancement, with three preset shapes, an off switch, reduced-motion support and a static fallback. Load it only on pages that use it. No fabricated content or performance claims. Draft creation, preview and activation remain separate. Screenshot previews must come from real rendered templates. Responsive and keyboard verification accompany changes.

## Shared customer surfaces

Shared customer surfaces default to a light neutral background, dark slate text and a restrained blue action color. Explicit saved site identities continue to take precedence.

Core-owned launch, Membership and SaaS surfaces use the safe published identity subset described in [Shared site UI](docs/SHARED_SITE_UI.md). Their presentation consumes standalone semantic tokens and retains module/session boundaries. Default commerce account styling is scoped to its own component, supports dark identity pairs, and uses native progressive disclosure for alternative sign-in methods. Theme overrides retain precedence.
