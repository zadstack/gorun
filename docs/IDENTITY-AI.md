# AI identity suggestions (optional module)

`identityai` is an optional module (`kernel.OptionalModule`) that asks a configured **text** AI connection for identity suggestions and writes them into the **Appearance → Identity draft**. It never writes the live identity and never calls a provider without a reviewed request and an explicit approval. This first stage produces **text only** (palette, fonts, taglines, a written logo brief); it does not generate an image, vector or animation and the UI says so. Logo generation and optional animation through a provider with a verified image capability, with the same cost gating, are follow-up work and are not claimed here.

## Turning it on

The module is an optional module like commerce, saas or membership: it is on unless `addons.identityai.enabled` is `false` (System → Modules, or the settings CLI), through `kernel.AddonEnabled`. The kernel evaluates the gate before any route or navigation is registered, so a disabled module leaves no page, no nav entry and no data. Being on only adds the page: nothing is sent to a provider without a reviewed, approved request. Turning it off keeps whatever drafts it produced; they are ordinary identity drafts.

## What it does

Page: **Appearance → Identity AI** (`/admin/appearance/identity/ai`, permission `settings.manage`).

1. **Brief.** Choose a saved AI connection (Settings → Connections, kind `ai`; each option shows provider, model and the last recorded test status, or "untested") or the site's writing settings, and describe the sector, audience, tone, what must stay and which tagline languages you want. A theme whose `theme.json` does not declare `identity` is refused up front, because colours and fonts would never be shown.
2. **Preview request.** The page shows the provider, model and host the request really goes to (the saved endpoint, or the writing settings' provider and model), the exact system and user prompt (the site name, current tagline, theme name and current accent are included; no content bodies, keys or other settings), and the **estimated cost**: about N input tokens and at most 1 500 output tokens (the call is capped to that) at the provider's public per-million prices copied on the date shown (`PricesAsOf` in `internal/identityai/pricing.go`). Prices match exact model ids or ids with a dated suffix and each row cites its source page; any other id gets no estimate and says so. OpenAI reasoning models (gpt-5 family, o-series) cannot be driven by the shared client (it sends `max_tokens`, they need `max_completion_tokens`): the select marks them "not supported here" and Preview refuses them with an explanation before any approval; use a gpt-4o or gpt-4.1 model, or an Anthropic model. The system prompt carries a version id (`identityai-prompt-v1`) that is part of the request fingerprint and of every audit row. The token count is rough (one token per three characters; Arabic usually needs more). Nothing is sent.
3. **Approve and generate.** Tick the approval box and press Generate. The reviewed request is owner-bound (another admin's token is refused), single-use, replaced by a newer preview of the same admin, and expires after ten minutes; a reused or expired token is refused (409) without a provider call. The approval is bound server-side to a fingerprint of the exact destination shown (and the model that will be called; a different model override is refused) (provider, endpoint, model, connection version and the stored credential, hashed; for the writing settings the `ai.*` rows including the encrypted key) and to the active theme. If any of them changed since the preview, Generate refuses (409, "changed since the preview") with no provider call, no draft write and no audit row, and asks for a new preview.
4. **Result.** The reply must be one JSON object with hex colours, fonts from the identity font lists, corners, spacing, Arabic and English taglines and a written logo brief. It is validated by the theme's own identity rules (colours, known fonts, text/background contrast) when merged into the **draft**; anything invalid is rejected and the draft is left untouched. One tagline goes into `site.tagline` (the chosen language, Arabic when both were requested); the other tagline and the logo brief are shown marked **not saved** so they can be copied. The page then links to Appearance → Identity, where the live preview shows the draft and Apply or Discard decide.

Credentials stay in `internal/admin`: the module receives three hooks at boot from `pkg/cli` (`identityAIHooks` in `pkg/cli/modules.go`): `Destination` (`admin.AIDestination`: what the operator is shown and the fingerprint of exactly those stored values, from one read), `Complete` (`admin.CompleteWorkAgentBounded`: capped reply, refuses with `ErrAIDestinationChanged` when the destination or the model no longer matches the reviewed fingerprint, checked from the same read that builds the request, and with `ErrAIModelUnsupported` for a model the shared client cannot drive) and `Connections` (`admin.ListAIConnections`, for the select). The module never reads a key. The identity draft is shared per theme: a generation merges into the current draft and the last writer wins, like the Identity page itself. Failures from the provider are logged without provider text and shown as a generic stage failure. Every call that reached the provider is audited as `identityai.generate` with provider, model, connection id, a short request fingerprint and the outcome (`ok`, `upstream`, `bad_reply`, `invalid`, `store_failed`).

## What it cannot do

- Produce a logo file, an SVG, an icon set or an animation in this stage. The "logo brief" is text for a human designer.
- Verify that a provider or model is suitable; the connection's last test status is shown as recorded, nothing is probed from this page.
- Guarantee the estimate: prices are copied from public lists on a fixed date and an account may be billed differently.

## Tests

`internal/identityai/module_test.go` boots the kernel with fake hooks (no network): disabled module → no page, no nav; enabled → page in EN and AR with the scope statement; no ready connection → explanation and no call; preview shows prompt and cost and makes no call; generate without approval refused; approved generate → one call, draft saved, live keys unchanged, audit row, token single-use; provider error, non-JSON, invalid colour and unknown font each leave an existing draft untouched and show a safe message; known and unknown models in the price table.
