# Integrations hardening — acceptance and operator notes

## Scope

Builds on the populated-inventory rendering fix in PR #124. Keeps the current admin design and
provider-agnostic storage/mail components, with improvements to saved-result safety, background
feedback, compact bilingual presentation and populated-account performance. No production
configuration, credentials, provider resources, site content or deployments are changed by this PR.

## Behavior

- HTML uses 100 resources per kind, independent page controls and saved-data search across all
  fetched rows. Provider `complete` and `count` are separate from local pagination. GET starts no
  provider clients or jobs. API inventory arrays retain the full saved resource list.
- Pending saved observations update in the browser: single in-flight GET, 10-second request
  timeout, 2-second initial interval, error backoff capped at 15 seconds, five consecutive failures
  or 90 reads maximum. Hidden/offline pages pause, completed observations stop, pagehide cleans up.
  Authentication redirects and malformed snapshots do not replace the page.
- Selective DOM replacement preserves settings fields, filters, focus and identity drafts keyed
  by Worker form action. Identity credentials belong to one configuration revision and are not
  transferred across account/token changes. Obsolete dynamic regions are removed. New account
  choices and section availability update independently.
- Historical snapshots remain inspectable. Additive API flags `accounts_current` and `actionable`
  distinguish current evidence. Outdated R2/Worker resources cannot authorize actions; expired
  identity evidence is not displayed as passed. R2 writes compare the original token/account in
  the transaction, while identity checks reject configuration drift before recording a result.
- Report `issues` identifies unavailable sections using stable sanitized codes; those forms are
  disabled. Observation metadata `error_key` distinguishes unreadable saved results from an empty
  successful discovery. Repair keys are localized in Arabic and English; technical permission
  names remain Cloudflare's labels. Excess permissions remain explicitly unknown.
- `observe.Service.ListWithRevision` shares the ordinary freshness/status rules but resolves
  revisions from the caller's request snapshot and evaluates enabled state once per list.

## Validation

- `go test ./internal/admin ./internal/observe ./internal/httpx -count=1`.
- Focused regression tests for populated HTML, account/token rotation, pending and expired
  evidence, read-time configuration mismatch, R2 transaction conflicts and Worker drift,
  positive current R2 binding, malformed observations, partial section failure, Unicode search,
  page bounds, escaping, full API coverage and secret redaction.
- `go vet ./internal/admin ./internal/observe`, JavaScript syntax and `git diff --check`.
- `npx playwright test tests/integrations-live.spec.ts --project=chromium`: six checks including
  initial admin setup, desktop/mobile bounds, draft/focus preservation through reordered Workers,
  offline/backoff behavior, account-revision credential reset and removal of obsolete actions.
- Screenshots are generated by the actual-page browser test at 1440 and 390 pixels.

Detailed before/after measurements and caveats: [performance report](integrations-performance-2026-10-22.md).
Representative local large-account GET decreased from about 55 ms to 9 ms, and HTML from 2.25 MB
  to 264 KB. These are fixture-handler measurements, not Internet latency or provider benchmarks.
Small-account overhead and remaining full-snapshot decoding costs are disclosed in that report.

## Compatibility and follow-up

No schema migrations, new runtime dependencies, new provider permission requests or paid-service
activation. Manual S3 binding remains available; discovered R2 binding now requires current
inventory evidence. Clients must handle HTTP 409 configuration conflicts by re-reading settings.

Browser polling deliberately reuses the existing authorized saved-data HTML GET; its response is
bounded by pagination. It does not execute provider checks or form writes. Backups, mail delivery,
provider writes and production rollout require their own acceptance; this PR does not claim them.

Merge/review the narrow rendering fix #124 before this dependent improvement, then release and
roll out the official artifact through normal verification. Production currently retains the
previously installed single-site rendering hotfix until that explicit rollout.
