# دليل إنشاء موقع في GoRun

ابدأ من **الموقع ← التصميم ← تصميم الموقع ← ابنِ الموقع** داخل لوحة الإدارة. تحتاج صلاحيات إعدادات الموقع وإنشاء المحتوى وتعديله ونشره وإدارة القوائم لإنشاء الموقع وتفعيله. تبويب «الهوية البصرية» يشترك معه في مساحة التصميم، لكنه يحتفظ بحفظه اليدوي المنفصل. المعالج يجهز صفحات قابلة للتعديل؛ الموقع الحالي يظل كما هو حتى تختار **نشر وتفعيل الموقع**.

لتبديل لغة لوحة الإدارة (عربية ⇄ English) استخدم زر اللغة في الشريط العلوي؛ لغة الموقع العامة تُضبط في **الإعدادات ← عام**. راجع [مساحة الإدارة](ADMIN_WORKSPACE.md).

## 1. اختر التصميم

| التصميم | الصفحات الجاهزة | مناسب لـ |
|---|---|---|
| حديث — Modern (`business`) | الرئيسية، من نحن، الخدمات، الأعمال، التواصل | هوية نظيفة حادة للشركات والخدمات |
| بسيط — Minimal (`portfolio`) | الرئيسية، الأعمال، النبذة، الخدمات، التواصل | هوية هادئة للأعمال الشخصية والمشاريع |
| سيرف — Serif (`magazine`) | الرئيسية، عن الموقع، الموضوعات، التواصل | هوية تعتمد على الخط للقراءة والمحتوى |

لكل تصميم قائمة وتذييل وصفحات داخلية ومقالات وبحث وحالات فراغ وخطأ. القوالب الثلاثة تدعم العربية والإنجليزية والموبايل وتستخدم صورًا ورسومات محلية. المجلة تعرض المقالات المنشورة فعليًا؛ لا ينشئ المعالج مقالات أو أعمال عملاء حقيقية تلقائيًا.

## 2. اكتب بيانات مشروعك مرة واحدة

اسم الموقع ولغته مطلوبان. باقي بيانات النشاط اختيارية، ويمكن استكمالها من محرر الصفحات لاحقًا.

| الحقل | أين يُستخدم؟ |
|---|---|
| الوصف المختصر | وصف الموقع العام وترويسته، بحسب التصميم |
| وصف المشروع | نص الرئيسية، ملخصها ووصفها لمحركات البحث |
| النبذة وقصة المشروع | صفحة النبذة أو «من نحن» |
| الخدمات أو الموضوعات | عناوين الخدمات؛ وفي المجلة موضوعاتها |
| البريد والهاتف والعنوان | قسم التواصل في صفحة التواصل |
| الشعار | ترويسة الموقع عند التفعيل، وفي معاينة المسودة قبل التفعيل |
| الصورة الرئيسية | قسم البداية بالرئيسية والصورة المميزة للصفحة |

اكتب من خدمة واحدة إلى ست خدمات أو موضوعات، كل منها في سطر لا يزيد عن 120 حرفًا. ترك القائمة فارغة يُبقي أمثلة التصميم لتعديلها لاحقًا.

وصف المشروع يقبل حتى 1600 حرف، والنبذة حتى 6000 حرف ضمن حجم النص المقبول. عند ظهور تنبيه حجم النص قلّل طوله؛ يظل النموذج محتفظًا بمدخلاتك ولا تُنشأ صفحات لبيانات غير صالحة.

استخدم **اختيار الوسائط** للشعار والصورة الرئيسية. يمكنك اختيار صورة موجودة أو رفع صورة جديدة من النافذة نفسها. أضف وصفًا بديلًا مناسبًا في مكتبة الوسائط؛ تستخدم الصورة الرئيسية وصفها المحفوظ، أو اسم الموقع عند غيابه.

ترك الصورة الرئيسية فارغة يُبقي رسم القالب. ترك الشعار أو بيانات التواصل فارغة يحافظ على إعدادات الموقع الحالية؛ زر إزالة اختيار الشعار في هذا النموذج لا يمسح شعار الموقع المنشور.

## 3. راجع الهوية ثم جهّز المسودة

كل تصميم يبدأ بألوان وخط وعرض مناسبين له. يمكنك تغييرها؛ التحقق يمنع الألوان ذات التباين غير المقبول.

اختر **تجهيز مسودة الموقع**. تظهر قائمة الصفحات وروابط التعديل والمعاينة. في هذه المرحلة:

- الصفحات والقائمة الجديدة مسودات، ولا تُعرض للزوار.
- المعاينة تُظهر التصميم المختار وترويسته وتذييله وروابطه وشعاره الجديد.
- نماذج المعاينة معطلة؛ اختبر إرسال التواصل في الموقع المنشور لاحقًا.
- يمكنك تعديل النصوص والصور والأقسام وترتيبها في كل صفحة.

استبدل نماذج الأعمال والصور والنصوص التجريبية بمحتواك قبل تسليم الموقع. بيانات النشاط لا توفر مشاريع أو شهادات عملاء تلقائيًا.

إذا انقطع التجهيز، أعد إرسال النموذج نفسه لاستكمال الصفحات الحالية. بيانات النشاط تُثبت عند بداية المسودة؛ تغييرها أثناء إعادة محاولة مسودة قائمة لا يستبدل البيانات التي راجعتها. لبدء بيانات مختلفة اختر تجهيز مسودة جديدة.

## 4. فعّل الموقع الذي راجعته

اختر **نشر وتفعيل الموقع** من صفحة المراجعة. التفعيل ينشر الصفحات ويطبق الرئيسية والقائمة واللغة والقالب والهوية وبيانات التواصل والشعار المقدمة معًا.

إذا تغيرت الصفحات بعد تحميل المراجعة، أعد تحميلها وراجعها قبل التفعيل. إذا حُذفت صورة مختارة من المكتبة، يظهر تنبيه مع رابط تجهيز مسودة جديدة بالصور الصحيحة، ويظل الموقع الحالي دون تغيير.

التفعيل لا يحذف المحتوى القديم ولا يلغي نشره تلقائيًا. راجع الصفحات القديمة إن كنت تغير نشاط الموقع أو محتواه.

بعد التفعيل، الحفظ التلقائي داخل محرر الأقسام يحفظ المسودة فقط. استخدم النشر الصريح لتحديث الصفحة التي يراها الزوار.

أسفل محرر الأقسام يظهر **سجل التخطيط**: لقطات الحفظ والنشر والاستعادة. **معاينة** تفتح اللقطة دون تطبيقها، و**استعادة إلى المسودة** تستبدل المسودة الخاصة فقط بعد تأكيد كلمة المرور حديثًا (خلال نافذة إعادة المصادقة)، وتبقى الصفحة العامة كما هي حتى تنشر من جديد.

## 5. اقرأ شاشة جاهزية الموقع

افتح **المظهر ← جاهزية الموقع**، أو رابط الجاهزية الظاهر بعد التفعيل.

| الحالة | معناها | التصرف المناسب |
|---|---|---|
| صالح | الفحص المحلي المحدد نجح | راجع الدليل المكتوب بجوار النتيجة |
| راجع | معلومة ناقصة أو مثال يحتاج استكمالًا | افتح رابط التعديل واستكملها |
| يحتاج إصلاحًا | مشكلة مؤكدة، مثل صورة محلية مفقودة أو رابط إلى مسودة | أصلحها ثم افتح الجاهزية مرة أخرى |
| غير متحقق | الفحص غير متاح أو يحتاج اختبارًا فعليًا | نفذ الاختبار المناسب؛ لا تعتبره نتيجة نجاح |

تشمل الفحوص الرئيسية العامة والقالب والهوية والشعار والقائمة، والنصوص التجريبية وأوصاف الصور وملفاتها، ووصف الرئيسية والتواصل وإعداد البريد والعنوان العام والنسخ الاحتياطية.

تظهر صفحة أول مشكلة نص أو صورة مع رابط محررها متى أمكن تحديدها. اكتشاف النصوص التجريبية يعتمد على عبارات معروفة؛ راجع المحتوى بنفسك أيضًا.

الشاشة للقراءة فقط ولا ترسل بريدًا أو تزور روابط خارجية. تفحص حتى 100 محتوى عام منشور و200 صورة و200 رابط قائمة؛ يظهر الفحص الجزئي بوضوح. وجود إعداد SMTP لا يثبت تسليم البريد، ووجود عنوان HTTPS لا يثبت DNS أو TLS أو تشغيل الخادم. العنوان المحلي مناسب لتجهيزك الحالي.

## 6. اختبر التواصل واحفظ نسخة

بريد المعالج يصبح مستلم التواصل الافتراضي. إذا حددت مستلمين صريحين في إعدادات النماذج فلهم الأولوية، وتظل إعدادات إرسال التنبيهات الحالية سارية. راجع **رسائل النماذج** وإعداداتها.

بعد ضبط البريد، أرسل رسالة من صفحة التواصل المنشورة وتحقق من تسجيلها داخل **رسائل النماذج** ومن وصولها إلى صندوق البريد المقصود. تسجيل الرسالة وحده لا يثبت وصول البريد.

من **النظام ← النسخ الاحتياطية** أنشئ نسخة واحفظ ملفي قاعدة البيانات والأرشيف معًا. نتيجة الجاهزية تثبت وجود زوج الملفات فقط؛ خطوات التشغيل والاستعادة موضحة في [دليل الإنتاج والاستعادة](PRODUCTION.md).

## 7. تبديل القالب بعد أول موقع

- **المظهر ← القوالب:** فعّل `default` أو `business` أو `magazine` أو `portfolio` أو `docs`. التفعيل يغيّر العرض فقط ولا ينشئ صفحات البداية.
- لإنشاء صفحات جاهزة مع التصميم الجديد: **المظهر ← ابنِ موقعك** من جديد، راجع المسودات، ثم **نشر وتفعيل الموقع** (ينشر المجموعة ويطبّق القالب والهوية معًا).
- تخصيص ملفات القالب الفعّال: مسودات من اللوحة أو REST/MCP تُحفظ تحت `<data>/overrides/<theme>/`؛ التفاصيل في [THEMES.md](THEMES.md).
- القوالب الخمسة باختصار: [DEFAULT-THEMES.md](DEFAULT-THEMES.md).

## حدود هذه المرحلة

المعالج يجهز مواقع المحتوى والخدمات ويملأ البيانات المقدمة. لا يولد موقعًا من وصف ذكاء اصطناعي، ولا ينشئ متجرًا مخصصًا أو يضبط الدومين والبريد تلقائيًا. دليل المطور للقوالب والأقسام موجود في [THEMES.md](THEMES.md).

## English — first site and theme switch

1. Sign in as admin. Optionally switch the admin UI with the top-bar locale control ([ADMIN_WORKSPACE.md](ADMIN_WORKSPACE.md)).
2. Open **Appearance → Build your site**, pick Business / Portfolio / Magazine, fill identity fields, **Prepare draft site**.
3. Edit drafts in the section builder; the live site is unchanged until **Publish and activate site**.
4. Check **Appearance → Site readiness**, then test the published contact form and take a backup ([PRODUCTION.md](PRODUCTION.md)).
5. To change look only: **Appearance → Themes** and activate a catalog slug. To get that theme's starter pages, run Build your site again and activate explicitly. Activating a theme alone does not create pages.


## أقسام مكتبة الثيم داخل الباني

في باني الصفحة، اختر «مكتبة أقسام الثيم» من «طريقة عرض القسم» للقسم الرئيسي أو المميزات أو الأسئلة الشائعة. وتبدأ أقسام «خطوات»، «مقارنة»، «معاينة المنتج»، «صفوف نص ووسائط» (صورة ونص بالتناوب) و«مبدّل المزايا» (خيار واحد مفتوح في كل مرة، يعمل بلوحة المفاتيح ودون JavaScript) بالمكتبة مباشرة. يمكن أن تحمل الخطوات والصفوف وخيارات المبدّل صورة مع نص بديل؛ النص البديل الفارغ يعني صورة زخرفية. ويعرض قسم «دليل قابل للبحث» العناصر المنشورة من نوع محتوى عام تختاره (مثل post) بلغة الصفحة، مع نموذج بحث عادي يرسل `q` إلى الصفحة نفسها ويعرض عدد النتائج ورابطًا لعرض الكل، حتى 24 عنصرًا؛ النوع غير الموجود أو غير العام لا يعرض شيئًا والمسودات لا تظهر. الصفحات القديمة تبقى على تخطيط الباني الحالي ما لم تغيّر الخيار؛ لا يتم تحويل HTML المنشور إلى حقول تلقائيًا.

يمكنك تعديل العنوان والنص والروابط، وأرقام القسم الرئيسي، وأيقونات بطاقات المميزات وتمييزها، وخطوات القائمة، وأعمدة وصفوف المقارنة، والأسئلة والأجوبة. الخلفية تستخدم مكتبة CSS الحالية وألوان وخطوط الثيم. لمعاينة المنتج اختر صورة فعلية مع وصف بديل، أو فعّل رسم CSS التوضيحي مع تعليق يوضح أنه توضيحي وليس لقطة منتج حقيقية. لا يجري توليد صورة أو إرسال طلب ذكاء اصطناعي.

مشاهد hero المتحركة ومصدر المقالات لا يتوافقان مع المكتبة؛ يبقيهما التخطيط الحالي. امسح الخيارات غير المتوافقة يدويًا قبل التبديل. الرجوع إلى التخطيط الحالي يحتاج تأكيد إزالة الحقول الخاصة بالمكتبة. المعاينة والحفظ لا ينشران الصفحة؛ راجعها باللغة المناسبة ثم انشر صراحة. عند تعارض تعديل، انسخ تعديلاتك وأعد التحميل بدل تجاوز رمز الحفظ. عقد JSON وحدوده موضحان في [API](API.md#structured-theme-section-layouts).

### English — editable native sections

Choose **Theme section library** for hero/features/FAQ, or add Steps, Comparison, Product preview, **Text and media rows** (alternating image and copy) or **Feature switcher** (one option open at a time, built on native disclosure elements, so it works with the keyboard and without JavaScript). A **Searchable directory** lists the published items of a public content type you choose (for example `post`) in the page language, with a plain search form that sends `q` to the same page, a result count and a show-all link, up to 24 items; an unknown or private type lists nothing and drafts never appear. Steps, rows and switcher options may each carry an image with alt text; an empty alt marks it decorative. Existing pages retain their builder layout by default. Edit native content through structured fields, save a private draft, reload or preview, then publish explicitly. A CSS interface illustration is labeled and requires a caption; it is not an actual screenshot or an AI-generated image. Legacy hero scenes/feeds are incompatible with native mode and remain supported in the existing layout. No theme stylesheet is copied or replaced.

## صفحات حسب الغرض

من **المحتوى ← الصفحات** افتح «صفحة جديدة حسب الغرض» واختر الغرض (من نحن، خدمة، منهجية العمل، تواصل) والعنوان واللغة.
تُنشأ مسودة خاصة في المنشئ: تستخدم الواجهة عنوانك، وتبدأ بقية الأقسام فارغة ومخفية بعنوان بنيوي فقط، فلا يظهر للزوار
شيء لم تكتبه. صفحة التواصل تعرض نموذج التواصل الحقيقي. اكتب كل قسم ثم أظهره وانشر الصفحة. يُحفظ الغرض في حقل `purpose`،
فتربط القوالب إليها بـ`{{destination "contact"}}`.

### English — purpose pages

Under **Content → Pages**, open "New page from a purpose" and choose the purpose (about, service,
methodology or contact), the title and the language. It creates a private builder draft: the hero uses
your title, and every other section starts empty and hidden with only a structural heading, so nothing
you did not write reaches visitors. A contact page shows the site's real contact form. Write each
section, show it, then publish. The purpose is stored in the page's `purpose` field, so themes link to
the page with `{{destination "contact"}}`. The same draft can be created with `POST /api/v1/builder/pages`
or the MCP tool `create_purpose_page`.
